# CADCraft MCP App POC

Build locally from the repository root:

```sh
cargo run -p dagger-pipeline -- cad-craft-mcp-app --cadcraft-ref main
```

Use `--publish` for GHCR SHA/latest tags, or `--tag` for a custom local tag.
The manual Build CADCraft MCP App workflow accepts a branch, tag, or commit.

```sh
docker run --rm -p 8080:8080 -e PUBLIC_BASE_URL=http://localhost:8080 bionic-gpt-cad-craft-mcp-app:local
```

Open `/` to preview. Register the container's `/mcp` endpoint with Bionic and
request `open_cadcraft`. PUBLIC_BASE_URL must be browser reachable; use HTTPS
when embedding from HTTPS. Bionic may use an internal URL for MCP access.
The app resource declares the public origin for asset loading and WASM fetching;
the host must permit WASM compilation in its sandbox CSP.

The editor runs inside the host iframe. This POC adds no drawing-command tools,
authentication, or server-side persistence. File downloads depend on host sandbox
permissions. Bionic host support is a separate integration.

Acceptance: initialize MCP, list/call open_cadcraft, read its ui resource, verify
canvas rendering, resize, pan, and draw a line in an MCP Apps host and in Bionic.

The launcher is now an independent Cargo project with its own lockfile; no root
workspace membership or dependencies are needed. Dagger builds it separately
from upstream CADCraft. The minimal browser bridge is generated by Dagger, and
there is no Node runtime or host npm installation. The launcher currently
implements the small stateless JSON-RPC surface directly using Axum.
